# Codegen

[graphql-codegen](https://the-guild.dev/graphql/codegen)'s `typescript` and `typescript-resolvers`
plugins type every resolver from your SDL. Resolvers keep the signature `(parent, args, context, info)`
of graphql-tools, Yoga and Apollo, so the generated `Resolvers` type goes to `createSchema` as its
second generic. Graxia compiles the real output of both plugins in its own tests (a fixture with a
query, a mutation, subscriptions with and without `resolve`, an interface, a union, a custom scalar,
an enum with internal values and a mapper).

## Install and run

```sh
bun add -d @graphql-codegen/cli @graphql-codegen/typescript @graphql-codegen/typescript-resolvers
bunx graphql-codegen
```

## codegen.ts

Point `contextType` at the context written once with [`InferContext`](./context.md), so the resolver
context is never declared twice:

```ts
// src/context.ts
import { type ContextInit, type InferContext } from '@softistx/graxia';

export const plugins = [
	/* your plugins */
] as const;

export const context = async ({ request }: ContextInit) => ({
	user: await authenticate(request),
});
export type AppContext = InferContext<typeof context, typeof plugins>;
```

```ts
// codegen.ts: `schema` and `generates` paths are relative to the working directory;
// `contextType` and the `mappers` / `enumValues` modules are relative to the generated file.
import type { CodegenConfig } from '@graphql-codegen/cli';

const config: CodegenConfig = {
	schema: './schema.graphql',
	generates: {
		'./src/generated.ts': {
			plugins: ['typescript', 'typescript-resolvers'],
			config: {
				contextType: './context#AppContext',
				useTypeImports: true,
				// what resolvers return: the database row, not the GraphQL type
				mappers: { User: './models#UserRow' },
				// the enum's internal values
				enumValues: { Role: { ADMIN: 'admin', MEMBER: 'member' } },
				scalars: { Date: 'Date' },
			},
		},
	},
};
export default config;
```

## Passing `Resolvers` to `createSchema`

```ts
import { createGraxia, createSchema } from '@softistx/graxia';
import { context, plugins, type AppContext } from './context';
import type { Resolvers } from './generated';

const resolvers: Resolvers = {
	Query: { me: (_parent, _args, ctx) => ctx.user },
	User: { joined: (user) => new Date(user.at) },
	Subscription: {
		clock: {
			subscribe: async function* () {
				yield { clock: 1 };
			},
		},
	},
};

const schema = createSchema<AppContext, Resolvers>()({ typeDefs, resolvers });
createGraxia({ schema, context, plugins }).serve({ port: 3000 });
```

`createSchema` refuses a resolver map generated for another context than `AppContext` (the
`resolvers` option fails with `Property ''createSchema<Ctx>: these resolvers expect another context (see expected)'' is missing`; see [Troubleshooting](../troubleshooting.md)). Resolver
functions annotated with a different context are refused by the generated types themselves.

## Notes

- **Mappers** and **enumValues** work as in any server: graxia sets an enum's internal values from
  the `Role` resolver and returns whatever the resolvers return, the mapper type included.
- **Enums mapped to an external module** (`enumValues: { Role: './models#RoleValue' }`) make
  codegen emit `export { Role }` over a type-only import, which fails under
  `verbatimModuleSyntax`. Give the values inline, as above.
- **`resolve` of a subscription** receives the event typed `any` by codegen: annotate it
  (`resolve: (event: { title: string }) => ...`).
- The generated file is regenerated by you, not by `build`. Commit it.

## Coming from Yoga / Apollo

| You write                                       | In graxia                                                 |
| ----------------------------------------------- | --------------------------------------------------------- |
| `(parent, args, context, info) => ...`          | the same, `context` is your `InferContext` type           |
| `{ subscribe, resolve }`                        | the same                                                  |
| `__resolveType`, `__isTypeOf`                   | the same                                                  |
| `new GraphQLScalarType({ ... })`                | the same, under the scalar's name                         |
| `{ RED: 1 }` for an enum                        | the same                                                  |
| `makeExecutableSchema({ typeDefs, resolvers })` | `createSchema<Ctx, Resolvers>()({ typeDefs, resolvers })` |
| `context` factory in `createYoga`               | `context` option of `createGraxia`                        |
