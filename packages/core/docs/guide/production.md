# Production

A checklist to ship a graxia server: what `NODE_ENV=production` changes, a complete configuration,
what to set behind a proxy, how to shut down, and what to check before the first deploy. Every
default below is checked by `src/production.test.ts` and `src/development.test.ts`, which run the
same instance with `NODE_ENV` set and unset.

## What `NODE_ENV=production` changes

graxia reads `NODE_ENV` once, when `createGraxia` runs. Four defaults follow it; the rest is the
same in every environment, and secure from the start.

| option                  | development (unset) | production         | guide                                                   |
| ----------------------- | ------------------- | ------------------ | ------------------------------------------------------- |
| `introspection`         | `true`              | `false`            | [Security](./security.md#introspection-and-suggestions) |
| `suggestions`           | `true`              | `false`            | [Security](./security.md#introspection-and-suggestions) |
| `trustedDocuments.mode` | `mixed` (APQ on)    | `strict` (APQ off) | [Trusted documents](./trusted-documents.md)             |
| `onUnexpected`          | `console.error`     | silent             | [Errors](./errors.md)                                   |

Set `NODE_ENV=production` in your process manager or image, never in code. Without it you ship
introspection, "Did you mean" hints and arbitrary queries.

Always on, in every environment (turn them off only on purpose):

- Errors are masked: a plain `Error` becomes `Unexpected error.` with a correlation id
  ([Errors](./errors.md)).
- CSRF: a `GET`, or a `POST` that is not JSON, needs a preflight header; a WebSocket upgrade from
  another origin is refused ([Security](./security.md)).
- Limits: `tokens` 15 000, `nesting` 1 000, body 1 MiB, `depth` 12, `aliases` 30, `directives` 50,
  `rootFields` 20, `cost.max` 5 000 ([Limits and caches](./limits-and-caches.md)).
- Batching is off, and the request id is generated by the server, never taken from the client
  ([GraphQL over HTTP](./http.md)).

`trustedDocuments` only exists when you give the option: without it queries run as sent. In
production, always give it.

## A recommended configuration

One instance with trusted documents, a rate limit shared across instances, Redis for the
PubSub, OpenTelemetry and an error logger. It needs `@graxia/redis` and the tracing packages of
[OpenTelemetry](./telemetry.md#setup).

```ts
// server.ts
import {
	createGraxia,
	createSchema,
	fieldRateLimit,
	type PubSub,
} from '@graxia/core';
import { redisPubSub } from '@graxia/redis';
import { redisLimit } from './redis-limit'; // the adapter of Rate limiting, "Stores"

type Topics = { tick: { n: number } };
type AppContext = {
	ip: string | undefined;
	pubsub: PubSub<Topics>;
	signal: AbortSignal;
};

const schema = createSchema<AppContext>()({
	typeDefs: `
		type Query { hello: String signIn(email: String): Boolean }
		type Subscription { tick: Int! }
	`,
	resolvers: {
		Query: { hello: () => 'world', signIn: () => true },
		Subscription: {
			tick: {
				subscribe: (_root, _args, { pubsub, signal }) =>
					pubsub.subscribe('tick', { signal }),
				resolve: (event: { n: number }) => event.n,
			},
		},
	},
});

// The manifest your client toolchain generates (Relay, graphql-codegen or Apollo).
const manifest: Record<string, string> = await Bun.file(
	'persisted-documents.json',
).json();

const pubsub = redisPubSub<Topics>({ url: process.env['REDIS_URL'] });

export const graxia = createGraxia({
	schema,
	context: ({ request }) => ({
		ip: request.headers.get('x-real-ip') ?? undefined, // set by your proxy
		pubsub,
	}),
	trustedDocuments: { manifest }, // strict when NODE_ENV=production
	plugins: [
		fieldRateLimit<AppContext>({
			fields: { signIn: { limit: redisLimit(5, 60_000), single: true } },
		}),
	],
	csrf: { sameOrigin: { allowedOrigins: ['https://app.example.com'] } },
	shutdownTimeout: 10_000, // the default; dispose() waits this long, twice at worst
	onUnexpected: (error, { correlationId, phase }) =>
		console.error(
			JSON.stringify({ level: 'error', correlationId, phase }),
			error,
		),
});

await graxia.ready; // fail fast when a plugin's setup failed
```

Notes on each choice:

- **Trusted documents.** Build the manifest in CI with your client toolchain and ship it with the
  server; `strict` then runs only those documents. See
  [Trusted documents](./trusted-documents.md#manifest-formats).
- **Rate limit.** `memoryFieldLimit` counts per process: with several instances the real limit is
  the limit times the instances. Use a shared store. `single: true` makes `signIn` selectable once
  per operation, so aliases cannot multiply attempts. See [Rate limiting](./rate-limiting.md).
- **PubSub.** `createMemoryPubSub` delivers inside one process. With several instances, a mutation
  on one must reach subscribers on the others: use `redisPubSub`. Delivery is at most once.
- **Telemetry.** On when `@opentelemetry/api` is installed; register your OTLP provider before
  `createGraxia` (see [OpenTelemetry](./telemetry.md#setup)). Leave `resolverSpans` and
  `document` off unless you are tracing a problem: they cost a span per field and may record
  literals.
- **Logging.** `onUnexpected` is silent in production by default; give it your logger, with the
  `correlationId` that the client also received in the error.

### Caches

The parse and validation caches (`caches`) are in memory per process, on by default and bounded
(see [Limits and caches](./limits-and-caches.md)); leave them on. Redis does not hold them. It
holds what must be shared: the PubSub above and, if you run `mixed` mode with APQ on a public
endpoint, the registered queries:

```ts
import { redisCache } from '@graxia/redis';

export const apqStore = redisCache({ prefix: 'graxia:pq:' });
// createGraxia({ schema, trustedDocuments: { mode: 'mixed', store: apqStore } })
```

`redisCache` sets no expiry on a registration, so give that Redis a `maxmemory` and an eviction
policy (`allkeys-lru`) and keep the prefix apart from your other keys. In `strict` mode APQ is
off and the store is only read, so most deployments need none.

## Behind a proxy

- **Client address.** Without `key`, `fieldRateLimit` counts the connection address, which behind
  a proxy is the proxy's. Count a header only your proxy sets (`x-real-ip`, or the right-most
  trusted entry of `x-forwarded-for`), through the context's `ip` as above or `key`. Strip that
  header from incoming requests at the edge.
- **Origins.** `sameOrigin` compares the request's `Origin` with the origin of the request URL,
  which behind a proxy is the internal one. List the public origins of your web apps in
  `csrf.sameOrigin.allowedOrigins` (scheme, host and port, no path). Without `sameOrigin`, only the
  header check runs for HTTP.
- **WebSocket `Origin`.** An upgrade from a browser origin that is not allowed is refused with 403,
  with `sameOrigin` on or off: list the origins that open sockets. Make the proxy forward
  `Upgrade` and `Origin`, and raise its idle timeout above `subscriptions.ws.keepAliveMs` (12 000 ms
  by default) so keep-alive pings hold the socket open. The same holds for SSE
  (`subscriptions.sse.keepAliveMs`, [Subscriptions](./subscriptions.md)).
- **Bun's idle timeout** (10 s) and **CORS** are not graxia's: see
  [Subscriptions](./subscriptions.md#bun-idle-timeout); set CORS at the proxy or in your host `fetch`.

## Shutdown

On `SIGTERM`, stop taking work and let in-flight operations finish. `server` is the `Bun.serve`
handle of [Health checks](#health-checks):

```ts
// main.ts, after Bun.serve
process.on('SIGTERM', async () => {
	await graxia.dispose(); // waits up to `shutdownTimeout` (10 s), see below
	await server.stop();
	process.exit(0);
});
```

`dispose` makes `graxia.fetch` answer 503 `SHUTTING_DOWN` (your own routes, such as `/healthz`,
keep answering until `server.stop()`), ends open event streams at once, closes every WebSocket with
1001, waits up to `shutdownTimeout` (10 000 ms by default; `dispose({ timeout })` overrides it) for
the other operations, then aborts their `signal` and waits as long again: at most twice the timeout.
Set your orchestrator's grace period above that (30 s with the default). With `graxia.serve()`,
`dispose` also stops the server, so `server.stop()` is only for your own `Bun.serve`. Close what you
opened afterwards (`pubsub.dispose()`, the Redis client). See
[Context, cancellation and shutdown](./context.md#dispose-and-draining). Pass `signal` to every
outgoing call in a resolver so an aborted operation stops its work.

## Sizing limits and caches

The defaults suit an ordinary API. Size them from your clients, not from guesses:

- Log the `extensions.limit.actual` of refused operations while you roll out, and set `depth`,
  `aliases`, `rootFields` and `cost.max` to your largest legitimate operation plus headroom.
  With trusted documents every operation is known in advance: measure the manifest and set the
  limits just above its largest document.
- Mark expensive fields with `@cost` and lists with `@listSize`; lower `limits.bodyBytes` (1 MiB)
  to what your largest variables need.
- Memory grows with `caches.parse.maxBytes` and the number of in-flight operations. Set the
  container's memory limit from a load test, not from a guess.

## Health checks

graxia has no health route of its own, and introspection is off. Serve plain routes next to it
(or probe `{ __typename }`, allowed in production but, in `strict` mode, only as a trusted document):

```ts
// main.ts
import { graxia } from './server';

const server = Bun.serve({
	port: 3000,
	routes: {
		'/healthz': () => new Response('ok'), // liveness: the process answers
		'/readyz': () =>
			graxia.ready.then(
				() => new Response('ready'),
				() => new Response('not ready', { status: 503 }),
			), // readiness: every plugin's setup ran
		'/graphql': (request, server) =>
			graxia.isUpgrade(request)
				? graxia.upgrade(request, server)
				: graxia.fetch(request, { server }),
	},
	websocket: graxia.websocket,
});
```

## Before you ship

- [ ] `NODE_ENV=production` is set in the running process.
- [ ] `trustedDocuments` has the manifest your current client build produced, and a query sent in
      full answers `PERSISTED_QUERY_ONLY`.
- [ ] `{ __schema { types { name } } }` is refused and an unknown field gets no "Did you mean".
- [ ] A resolver that throws answers `Unexpected error.` and your logger receives the original with
      the same `correlationId`.
- [ ] `csrf.sameOrigin.allowedOrigins` lists your public origins, and a socket from another origin
      is refused.
- [ ] The rate limit store is shared, and the key is a header your proxy sets.
- [ ] Limits are sized from the manifest; a depth bomb and an alias bomb are refused.
- [ ] The PubSub and the APQ store (if any) are Redis, not memory, when you run several instances.
- [ ] Traces reach your collector, and logs carry the `x-request-id` of the response.
- [ ] `SIGTERM` drains: start a subscription, send the signal, see it complete.
- [ ] Probes answer, and the orchestrator's grace period exceeds twice `shutdownTimeout`.
