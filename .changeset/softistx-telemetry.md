BREAKING (pre-1.0): Telemetry runs on the in-house `@softistx/telemetry` instead of `@opentelemetry/api`. The optional peer `@opentelemetry/api` `^1` is replaced by the optional peer `@softistx/telemetry` `^0.4.1`; without it graxia still traces nothing and wraps nothing. Migration: `bun add @softistx/telemetry` (and an exporter such as `@softistx/telemetry-otlp`) instead of the OpenTelemetry API and SDK packages, `createTelemetry('my-api', { exporters }).install()` instead of registering a tracer provider and a context manager, and `telemetry: { instance }` (a `Telemetry` from `createTelemetry`) instead of `telemetry: { tracer }`; a `tracer` option now throws `telemetry.tracer was replaced by telemetry.instance (…)`, and an invalid `instance` throws `telemetry.instance must be a @softistx/telemetry Telemetry`. Span names and attributes are unchanged. Differences: a failure that is an `AbortError` or a `TimeoutError` ends the span `cancelled` rather than `error`, and a WebSocket operation span is now a child of the upgrade's `graphql.request` span (same trace as the upgrade request's `traceparent`). The operation span records the first unexpected error only; `graphql.error.count` still counts all. The new type `TelemetryInstance` describes `instance` structurally.
